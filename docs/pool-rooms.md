# Sowaka Pool — live rooms contract (server ⇄ page)

Catalog key `pool`. Namespace `/pool` on the shared Socket.IO server (path `/connect/socket`). Ticket marker in the page head: `<!--POOL-TICKET-->` → `window.__POOL = { ticket, hopTicket }` (`pool` is in TICKETED in game-catalog.controller.ts). Rooms per org, 4-digit codes, two or four players (`size`, chosen by the host): a table for 4 is two teams of two, seats 0 & 2 against seats 1 & 3. A `room:join` into a full table is refused `409 "That table is full."` (watchers are not in v1).

**v2 (7 Nov 2026):** tables for four, no called pocket (the 8 in any pocket wins once the shooter's group is cleared; early or with a foul it loses), a ball potted on the break gives the breaker its group.

## Engine (shared, deterministic)
`backend/src/shared/pool/engine.ts` — pure, no imports, no Math.random. Exports:
- constants `L=2, W=1, R=1.125/39, POCKETS, CORNER, SIDE, MOUTH, FRICTION, VMAX`, `rack(): Ball[]`
- `simulateShot(balls: Ball[], shot: Shot): { balls: Ball[]; events: ShotEvent[]; steps: number }` — fixed step 1/240 s with sub-steps; identical output everywhere for the same input (plain floating-point arithmetic, no randomness). `shot = { aim: number (radians, world frame), power: 0..1, spin: { top: -1..1, side: -1..1 } }`.
- `resolve(state: RuleState, after: Ball[], events: ShotEvent[]): RuleOutcome` (`after` = the balls `simulateShot` returned) — the 8-ball rules exactly as the single-player page: break (kitchen, ≥4 balls to a rail or a pot, 8 on the break re-spotted), open table, group by the first legally potted ball (on the break too), fouls (scratch, no contact, wrong first ball incl. the 8, no rail after contact), ball in hand (anywhere; behind the head string after a break foul), the 8 only after the group: in any pocket it wins, early or with a foul (a scratch) it loses. No called pocket. `turn: 0|1` is the **side**: a player at a table for two, a team at a table for four — the engine never knows about seats.
- Types `Ball { n, x, y, vx, vy, on }`, `ShotEvent` (`hit {a,b,v}`, `cushion {n,v}`, `pocket {n,p}`, `scratch`), `RuleState { balls, turn: 0|1, groups: [null|'solid'|'stripe', null|'solid'|'stripe'], open, inHand, kitchen, breakShot }`, `RuleOutcome { foul: string|null, keepTurn, winner: 0|1|null, next: RuleState, message }`.

## Room view (per player, `room:state {room}`)
```
{ code, status: 'lobby'|'playing'|'over', you: userId, hostId, open, serverNow, size: 2|4,
  players: [{ userId, name, photoUrl, online, left, team: 0|1, group, pottedCount }], // seat order; team = seat % 2; seat 0 breaks the first game; left: walked out mid-game, seat kept until the room re-seats
  invited: [{ userId, name, photoUrl }],
  turn: 0|1,                                                              // the side whose inning it is (the engine's turn)
  shooter: seatIndex,                                                     // who shoots now (0..size-1); turn === shooter % 2
  balls: [{n,x,y,on}], inHand, kitchen, open8: bool /* table open */, breakShot,
  onEight: bool,                                                          // the shooter's group is cleared: the 8 is next (any pocket)
  shotClock: { endsAt } | null,                                           // 30 s per shot, server clock, counted from the end of the replay
  replayUntil: epochMs,                                                   // the last shot is still rolling until then; a shot before it is refused
  lastShot: { seq, by: seatIndex, aim, power, spin, from: {x,y}, events: ShotEvent[], balls: [...after], steps, at } | null,
  message: string|null, result: { winner: 0|1 /* side */, reason: 'eight'|'foul'|'left'|'away' } | null, gameNo, wins: [n,n] /* per side */ }
```
The page replays `lastShot` with `simulateShot` from `lastShot.from` positions (which it already has), then snaps to `lastShot.balls`. `lastShot.steps` is how many 1/240 s steps the engine ran (the replay's length); `at` is the server time the shot was taken. The server starts the next shot clock at `replayUntil = at + steps/240 s + 300 ms` (20 s at most) and fouls the shooter 1.5 s after `shotClock.endsAt`, so a shot sent at 0 still counts. `balls` is empty in the lobby. The breaker starts with ball in hand in the kitchen (`inHand`, `kitchen`, `breakShot` all true): a `pool:place` before the break is optional. No chat in v1.

`result.reason`: `eight` the 8 potted after the group; `foul` the 8 lost (early, or with a scratch); `left` the other side left mid-game; `away` the other side was offline 90 s mid-game. `wins` counts games won in this room per side.

**Seats and innings at a table for four.** Each side's seats take innings in turn: side 0 is seats 0, 2, 0, 2…, side 1 is seats 1, 3, 1, 3…. A shooter who keeps the table (a legal pot of their own group, or any pot on the break) shoots again; when the inning passes (a miss, a foul, a timeout) the other side's next seat in its rotation shoots, and the side's rotation pointer moves on. `shooter` is always the seat whose shot the server waits for; ball in hand (`pool:place`) and `pool:shot` are accepted from that seat only. Group and `pottedCount` are per side (both teammates show the same group). A seat is credited with every ball of its side's group it sank itself (a ball sunk while the table was open counts for whichever side ended up with that group; the opponents' balls it knocked in are nobody's); a side's `pottedCount` is the sum of its seats' credited balls, a seat that has since left included. The first game: seat 0 breaks; a rematch: the losing side breaks with its lower seat. Mid-game, a player leaving a table for four is dropped from the rotation and the partner plays on alone: the seat is kept (`players[i].left = true`, `online` false) so nobody else's seat moves, and that person is out of the room; a side with nobody left forfeits (`left`); a side whose every player is offline 90 s forfeits (`away`); one offline player of a pair simply times out on their shots. `final` has a line per player: own `potted` (the balls that seat is credited with), `won` by side, `score` = potted×100 + 1,000 for the win — except someone who walked out mid-game: `won: false`, `score: 0`, nothing recorded or paid for them, their tally not bumped. A game that ends with a seat gone (the 8, or a side away) stays on its podium like any other (`result`, `lastShot`, `final`, so everyone sees the winning shot); the lobby re-seat happens on `room:again`. A leave that itself ends the game (the last player of a side going) sends the room to the lobby at once, as at a table for two.

## Events (client → server; all acked `{ok,data}|{ok:false,status,message}`)
- `room:hello` → `{ room|null, rooms: [{code, host: {userId,name}|null, players: [{userId,name,photoUrl}], status, size, seatFree, createdAt}], invites: [{code, from: {userId,name,photoUrl}, players, createdAt, expiresAt}] }` (`rooms` = the company's open rooms, those with a seat first)
- `room:host {open, size?: 2|4}` → room (`size` defaults to 2; it cannot change once anyone else has joined) · `room:join {code, rejoin?}` → room (a `rejoin` only puts back someone still seated: 404 otherwise) · `room:quick {size?}` → room (the oldest open lobby of that size with a seat — any size when omitted — else a new open room of your own, size 2 unless given) · `room:leave` · `room:invite {userId}` → `{invited:true}` (same company only; push scenario `pool_invite`, data `{destination:'game_challenge', gameKey:'pool', challengeId:'room:<code>'}`)
- `room:start` (host, all `size` seats taken, everyone online; `409 "Need two players to start."` / `"Need four players to start."`) · `room:again` (either player, from `over`: with both at the table a new game starts at once and the loser breaks; with the other player offline the room goes back to its lobby; `409 "There is no finished game to replay."` in a lobby, `409 "The game is still on."` mid-game)
- `pool:place {x,y}` → room (ball in hand, your turn; validated: inside the table, not overlapping, in the kitchen when required; may be moved again until the shot; accepted during the replay)
- `pool:shot {aim, power, spin: {top, side}}` → room — only from the `shooter` seat, not before `replayUntil`; the server simulates, resolves, stores `lastShot`, pushes `room:state` to everyone at the table. Power and spin are clamped as the engine clamps them.
- Server → client: `room:state {room|null}` (null when the room is gone), `room:feed {kind: 'join'|'leave'|'host'|'foul'|'timeout', userId?, name?, text?}`, `room:invite {from, code, expiresAt}`, `room:fatal {code, message}`.
- Timeouts: at `shotClock.endsAt` (+1.5 s) the server fouls the shooter (ball in hand to the other; behind the head string if the break is still to come) — in the tick. Offline 90 s mid-game while the other player is online forfeits (`away`); both offline 90 s abandons the game: no winner, nothing scored, the room back in its lobby with a message. Leaving mid-game forfeits (`left`: scored and tallied) at a table for two, and drops the seat at a table for four (see Seats and innings). Whenever a player leaves a finished room, or `room:again` is asked for with a seat gone or someone offline, the room goes back to the lobby for those who stay, re-seated in joining order (the longest-present is seat 0 and host): the table, turn, `lastShot` and `result` are gone (they were indexed by the old seats), `wins` and `gameNo` stay, and a forfeit's `message` stays when a seat had gone. A seat is only ever taken in the lobby (`room:join`, `room:invite`, quick join): a running or finished room answers `409`.
- Rate buckets as Tile Up (host 5/60, join 10/60, invite 1,5, move 2,6 for place/shot, small 5,10 for the rest).

## Storage / service (copy Tile Up's shape)
`pool-store.ts` keys `pool:room:{org}:{code}`, `pool:seat:{org}:{uid}`, `pool:invites:{org}:{uid}`, `pool:lock:…`, `pool:once:…`, set `pool:live`; TTL 4 h. `pool-rooms-engine.ts` (pure: the room record, the view, start/place/shot/timeout/forfeit, `advance`) and `pool-room.service.ts` with `configurePool({now, random, notify, recordScore, awardPoints})`, `change(org, code, fn)`, effects `feed|invite|notify|finished|delete` (no kick in v1), the leased tick (500 ms) for the shot clock and presence. Finished: `recordServerScore(org,'pool', …)` for every player (score = own balls potted×100 + 1000 for the win; a 0 is not recorded), points = score ÷ 70 rounded, ≤ 25, via `payPoints` once per game (`claimOnce`). Check: `npm run pool:check` (`MONGODB_DB=pool_check`, no `REDIS_URL`), an in-process server on port 4321.

## Voice (walkie-talkie, 10 Nov 2026)
`backend/src/services/game-voice.service.ts`, attached to this namespace (and to any other game's later). Behind `companies.features.gameVoice`; `room:hello` answers `voice: true` where it is on. One mic per table (`pool:{org}:{code}`); only players seated there talk and hear.
- `voice:hold` → `{until, maxMs}` the mic is yours for 17 s, or 409 "Priya is talking". The others get `voice:floor {userId, name, until}`.
- `voice:clip {data (base64), mime, ms}` → `{}`: the holder's recording (≤ 15 s, ≥ 0.4 s, ≤ 160,000 base64 chars, an audio type) goes to everyone else at the table as `voice:clip {userId, name, mime, ms, data}`, and the mic is free (`voice:floor {userId: null}`).
- `voice:release` → `{}` let go without sending; a disconnect lets go too.
- Limits: the mic twice a second, a clip every 3 s per socket. Nothing is stored. Check: `MONGODB_DB=game_voice_scratch npm run game-voice:check`.
The app records (`Sowaka.voice.start/stop/cancel`, bridge v6: 16 kHz mono AAC in MP4, about 45 KB for 15 s); the page plays clips with Web Audio, one after another, the game's sounds dipped under them.
